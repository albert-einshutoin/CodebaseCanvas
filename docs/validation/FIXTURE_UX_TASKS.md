# CodebaseCanvas 予備評価 — 参加者用

資料版 A-draft-1。実施承認後に配布する課題です。

既存のNestJSコードを引き継ぎ、変更前に構造を調べる場面を想定します。使うデータはあらかじめ用意した手定義のsnapshotです。あなたの能力ではなく、製品の分かりやすさを確認します。

進行者が渡すJSONをFile選択して開始します。CLIで生成する必要はありません。各課題は5分です。Canvasとその付属表示を自由に使い、分かったこと、根拠として見た表示、分からなかったことを説明してください。操作方法は指定しません。時間内の最初の回答を残してから、必要なら進行者に助けを求められます。

この段階ではsource、fixtureの解説、JSONの直接閲覧、外部の検索/LLMを使わずに回答してください。データやContextを外部へ送る必要はありません。録画・発言引用・共有をする場合は別途同意を確認します。中断・辞退できます。

## T1 全体構造と共有component

このsnapshotに記録されたModuleを挙げ、全体の主要なつながりを説明してください。UsersServiceが登録されているModuleをすべて調べ、Canvasでの配置と、記録された所属の関係を根拠とともに説明してください。

## T2 Endpointとhandler

HTTP methodがGET、pathが `/users` に一致するEndpointをすべて調べてください。それぞれについてControllerとhandlerを区別し、どの表示を根拠に判断したか説明してください。

## T3 DIと確定できる範囲

OverrideControllerが要求するtokenを調べてください。表示された情報から、実際に実行される実装についてどこまで言えるでしょうか。言えることと言えないことを、根拠とともに説明してください。

## T4 unknownと局所／全体

UsersServiceのinstance method `choose` について、解析で分かった呼出し関係と、解決できなかった箇所を調べてください。このmethodの結果、UsersServiceに関連する結果、snapshot全体の集計を区別して説明してください。

## T5 Copy Context

UsersServiceについて、別の担当者へ渡せるContextを取得し、進行者が用意したローカル貼付け先で確認してください。対象、解析日時、根拠とそのconfidence、unknown、情報の短縮や省略の有無を説明してください。外部サービスへの送信はしないでください。

## 回答後

主観的に分かりにくかった画面・言葉・操作を教えてください。正解を探し直す必要はありません。
