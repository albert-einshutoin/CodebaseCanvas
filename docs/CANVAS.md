# Canvas grouping and explicit method LOD

The input is a validated, immutable `SystemGraph`. Canvas coordinates, selection and expansion never write back to its IDs, parentId, metadata, evidence, diagnostics or call counters. The hand-authored NestJS fixture is a UI input, not evidence that the current Analyzer emits a complete graph; production analyze remains nonzero/no-write until #17.

## Projection and state

`canvasState.ts` keeps `selectedNodeId`, `expandedOwnerId` (zero or one) and the import generation separate. Selection or zoom never expands a class. Show methods accepts only a module/controller/service/repository/class with direct methods verified by both parentId and contains. The UI reports counts **in this snapshot**, and disables Show for zero methods. The expanded owner's name and Hide control remain available when another node or a method is selected.

Selecting B while A is expanded keeps A expanded. Show on B switches owners. Hide or switching owners moves a selected disappearing method back to its previous owning class; other selected nodes stay selected. A new import generation resets selection and expansion even for matching IDs. The File input currently unmounts Canvas while loading and mounts it after successful validation. Invalid input renders an error, not the previous graph.

`graphToCytoscapeElements` is a pure projection. Default fixture: 40 nodes / 56 edges (file totals: 57 / 90). Expansion adds only the owner's method IDs, then retains every original edge whose endpoints are visible, including method contains/imports/calls and Endpoint→handler depends_on. It never invents or aggregates edges. Internal injects and its direction remain unchanged; its display label is Requests token.

The #23 kind filter supplies candidate IDs through `projectView`. Required ancestors are retained and counted separately from kind-matching nodes. Shared UsersService remains one node with no parent and its two canonical memberships; filtering one Module never reassigns it. Endpoints stay inside their Controller; expanded methods inside their owner. External/interface/DB nodes do not acquire proximity-based membership.

## Layout choice and configuration

Compared the previous breadthfirst view and built-in CoSE on the same fixture/viewport. CoSE with both existing and randomized initial positions stretched the Controller/Endpoint bounds excessively. Omitting ancestor-to-child layout forces also failed to improve this, so that experiment was discarded. Final rendering and layout both receive the complete projected canonical edge set.

Selected [fCoSE](https://github.com/iVis-at-Bilkent/cytoscape.js-fcose) 2.2.0 (MIT), whose Cytoscape peer requirement ^3.2.0 includes the existing 3.34.3. Added only this layout plugin, its cose-base/layout-base dependencies and @types/cytoscape-fcose 2.2.5. Exact direct versions and resolved transitive versions are in pnpm-lock.yaml; no optional layout-utilities extension or layout switcher.

Settings live in `canvasLayout.ts`: quality proof, animate false, fit false, nodeDimensionsIncludeLabels true, idealEdgeLength 100, nodeRepulsion 8000, numIter 1000, tile true, tiling padding 35, packComponents false. Initial import uses randomize true and explicit initial Fit (padding 40). Show/Hide uses randomize false and existing positions without automatic Fit. Placement axes are not dependency direction or execution order; follow arrows and relation names.

Layout runs synchronously with animate false, so there is no deferred layout completion/fit callback to apply to another graph. Selection, hover, background clear and parent rerenders do not invoke layout. Show/Hide diffs IDs, removes only hidden elements, adds only new elements, and seeds new methods near the pre-expansion owner position. Existing elements and viewport are retained; necessary force recalculation can still move nodes and take them outside the viewport. Explicit Fit is available. No position persistence or pixel-determinism guarantee.

Canvas suppresses selection callbacks during structural updates and controlled selection synchronization, preventing remove/unselect from overwriting the collapse selection. Ordinary node selection enforces one highlighted node even with modifier keys. Instance destruction also disposes listeners; ResizeObserver is disconnected on unmount.

## Style and limits

Leaves have bounded 155×64 dimensions, 14px kind/name labels and wrapping; full canonical names remain unchanged. Compound nodes get rectangular shapes after role styles, 28px padding and 18px headings; Module headings use 24px and stronger borders. Non-deprecated numeric leaf dimensions replace width/height:label. Edge labels appear for edges adjacent to a selected node or while hovered, including Requests token; edges themselves are not removed to reduce label density.

Dense crossings, long compound headings and full-fit label size are still layout limitations. Zoom/pan and explicit selection help inspect them. The node details/evidence panel is described below; search/filter/focus controls are described below; the full-snapshot diagnostics view is described below. No bundle-warning threshold change or unmeasured code splitting.

## Node details and explicit navigation (#22)

`nodeDetails.ts` reads the validated full snapshot, not the visible Cytoscape projection. It returns one-hop incoming/outgoing edges grouped by kind, each with its own evidence, direct methods using shared `directMethods`, all Module memberships, and bounded diagnostic groups. Copied arrays are sorted by kind/name/canonical ID or explicit evidence/diagnostic tuples; the graph is never modified. `NodeDetailsPanel.tsx` renders that model as text with a fixed-width desktop panel (stacked below at 850px), internal scrolling and keyboard-operable buttons/disclosures. Only the panel resets its scroll/disclosures on selection changes; Canvas never remounts for details.

Common definition location, node evidence, original UTC analyzedAt and analyzerVersion are displayed separately from edge evidence. Every confidence/source/location remains visible through evidence disclosures. `confirmed` does not establish runtime behavior. Class methods remain listed while collapsed; memberships come from Module contains edges, not a single parent. Endpoint controller/handler use exposes/depends_on; paths are not normalized again. Method static/instance and exact external specifiers reuse the existing canonical identity decoder through a narrow read API. No package inference from names. Database fields support strings or objects with string `name` and optional string `type`; other shapes/attributes are not guessed. Fixture User/Token models have no fields metadata.

Unknown scope is selected-node diagnostics plus direct method diagnostics (or declared handler for Endpoint), with unrelated same-file notices shown separately. Module selection does not recursively include components. Selected skipped sites sum only these method IDs; graph-wide recorded callAnalysis scope/mode and site counters are explicitly labeled. Diagnostic count, skipped sites, edge count and coverage are not interchangeable. No per-node coverage percentage or unknown edge is invented.

Details navigation is a separate generation-checked state action. Visible targets retain expansion and request viewport center without layout. Hidden methods verify parent+contains ownership, atomically set their owner as the sole expanded owner and the method as selected target, then request center. Canvas applies synchronous structural update/layout first, controlled selection second, viewport focus last. Request sequence changes for repeated navigation to the same ID. Normal selection/close/Show/Hide clear pending focus; graph reset discards old requests, including equal IDs in another snapshot. Close clears selection only. Coordinates are not persisted.

Security boundary stays at the existing import validator. Invalid paths, empty evidence and malformed Endpoint metadata are rejected before rendering. Optional valid absence is not repaired. No HTML execution, raw metadata viewer, URL auto-link, source read, external request, new dependency or schema change. Source labels remain repository-relative file[:line[–endLine]]. Search/filter/focus integration is described below. This panel does not implement #24 Context output; #25 global diagnostics use a separate selector and panel below.


## Symbol search, kind filters and dependency focus (#23)

State remains owned by React, not Cytoscape classes. `loadedGraph` is the validated immutable snapshot; `generation` identifies an import. `canvasState` separates `query`, `enabledKinds`, `selectedNodeId`, the single `expandedOwnerId`, `neighborhoodAnchorId`, and sequenced, generation-checked `focusRequest` (one viewport-center command). New imports reset all of them, even when node IDs match. Ordinary selection and typing never expand or enable kinds; typing only changes search candidates. Background/Close clears selection without moving the neighborhood anchor.

`canvasView.ts` contains pure search, projection and neighborhood selectors. Search indexes the **whole snapshot**, including filtered nodes and collapsed methods. It matches trimmed case-insensitive literal substrings in name, qualifiedName, Endpoint path / HTTP-method-and-path, and External exact specifier plus exported name. External specifiers use `nodeIdentityDetails`; only string `metadata.package` and `metadata.symbol` are additional fields. Other metadata is not serialized or guessed. Results are ordered by kind/name/ID with ordinal comparison, retain distinct identities, show at most 50 buttons and report total/displayed counts plus a refinement notice. Empty query, zero matches and truncation have different messages. Candidate labels include kind, file, owner, static/instance, handler and canonical ID as applicable. All content is text. A native search input, buttons and checkboxes provide keyboard operation; there is no combobox role, automatic Enter selection, regex engine or form submission handler.

All nine non-method kinds default ON. **Class and Interface are separate filters.** Methods have no global toggle: only the explicitly expanded owner's direct methods may appear, and only while that owner's kind is enabled. The expansion ID survives kind OFF; controls explain the hidden expansion target and ON restores it without import. `projectView` first selects non-method kinds, then direct methods, then canonical ancestors, then the adapter retains only original edges with both ends present. Ancestors never reveal siblings, other methods or adjacent nodes. For example Service ON / Module OFF leaves required Module frames with dashed borders and separate ancestor counts. Shared UsersService stays one parentless node with both original memberships; Endpoint/Controller and method/owner parents stay canonical. An all-OFF projection is valid and offers Reset kind filters. An empty snapshot is reported separately.

Filter removal clears an invisible selection and its viewport request, and clears an invisible neighborhood anchor. It never selects a substitute node. Existing explicit Hide/owner-switch behavior from #21 still returns a disappearing selected method to its visible owner; its disappearing neighborhood anchor is cleared, not transferred. Reset kind filters changes kinds only; Clear focus changes the neighborhood anchor only. Query, filters, selection, expansion and pan/zoom otherwise remain intact.

Focus neighbors captures the current selection as a fixed anchor. `directNeighborhood` uses all edge kinds, both directions, and only current visible endpoints. Strong nodes are the anchor and its deduplicated direct neighbors; strong edges are the visible original edges incident to the anchor. Self-loops and multiple edge kinds do not inflate node counts. Ancestors needed by strong children are **context frames**, excluded from neighbor counts unless independently incident to the anchor; they never become new traversal origins. Depth is exactly one, without automatic method expansion. Changing filters or Show/Hide recomputes around the same surviving anchor. Clicking another node keeps the anchor until explicitly replaced or cleared.

`canvasFocus.ts` applies dim classes without removing elements or changing viewport/layout. Leaf opacity dims unrelated nodes; compound frames change their own background/border/text paint, never compound opacity, so their children are not dimmed transitively. Selected/hover edge labels retain their existing inspected class. A sticky focus control shows the anchor and Clear focus while inspecting the Canvas or details.

Search results and details use the same generation-checked `navigate` action and `navigationLabel`. Explicit navigation clears neighborhood focus, preserves query and existing filters, and enables only the target kind if hidden (owner kind for methods). Hidden methods atomically switch the sole expanded owner and select the method. Buttons announce Reveal & go and method expansion before activation. Already-visible ancestor frames need no reveal. Details still read the full snapshot; hidden relationship targets remain present and carry Reveal labels, including Requests token, Statically called by and Handler for endpoint semantics.

Canvas structural effects are keyed by snapshot/generation and the actual visible ID set, not a newly allocated projection object. `updateCanvasElements` also returns without mutations for unchanged IDs. Query, ordinary selection, repeat navigation to visible IDs and Focus/Clear do not run layout. Necessary structural updates still use the existing synchronous fCoSE settings, controlled selection then center ordering, stable retained elements and viewport. Styling is a separate effect. Filter restoration needs no re-import; coordinates may move during a necessary layout.

Verification uses the hand-authored fixture (initial 40 nodes / 56 edges), independently built validated graphs, real headless Cytoscape and the existing Vitest runner. Tests check exact ID sets and canonical edge tuples, text guards/identity disambiguation, 50-result cap, hidden-method/reveal state, generations, context-only ancestors, all accepted edge kinds, self-loop deduplication, child effective opacity and unchanged elements/viewport/layout count on Focus/Clear. `reads`/`writes` remain rejected by the current wire contract and are not invented for UI tests. Browser checks use actual File input and disposable 0/1/60-node graphs. Captures/logs are outside the repository. These are implementer checks, not initial-user UX research, a callback-leak audit, #26 E2E or production analyzer evidence. Real Japanese IME composition and pinch gestures need separate manual verification; ordinary Enter in the search input has no navigation handler.


## Full-snapshot analysis and diagnostics (#25)

`graphDiagnostics.ts` reads only the validated original graph. Analysis summary reports file node/edge totals, diagnostic rows and original info/warning/error counts, UTC analyzedAt and recorded callAnalysis scope/mode/counters. These are independent of visible nodes, kind matches, method expansion and neighborhood focus. `nodeDetails` retains its existing bounded selected-node/direct-method/handler scope; UsersService skipped=3 and choose skipped=2 remain separate from the fixture's global skipped=7.

`AnalysisPanel` owns disclosure, severity/code/skipped-only filters and the displayed range. Its import-generation key resets those states for every file selection (including the same file or same IDs with different timestamps/counters); ordinary Canvas selection and navigation leave them intact. Reset diagnostic filters changes only diagnostic filters and their range. Codes come from the file, including unknown new codes. Initially all diagnostics match; the first 50 are rendered and Show 50 more reaches every remaining row. Total, matching and displayed counts are separately labeled. Changing any filter resets the range to 50. The skipped-call shortcut opens the list and clears severity/code filters, with the resulting all/all settings and skipped-only scope explicitly shown.

Rows use the existing ordinal comparison of JSON tuples `[relatedNodeId, file, line, code, severity, message, skippedCount]` on a copy. A sorted occurrence index is a display-only key within the import generation; identical ordinary diagnostics remain distinct rows. The location shown for a diagnostic is its own optional file/line, never the node definition. Related node buttons separately identify kind, owner, static/instance and canonical ID using shared search descriptions. File/global notices with no related ID have no navigation button or fabricated source link. Invalid related IDs, paths, line-without-file and call totals still fail the unchanged import validator.

Related buttons use #23 `navigationLabel` and the shared generation-checked navigate action. Visible targets select/center; hidden targets reveal only the required kind, verify method ownership and expand the owner before highlight/center. Query and unrelated kinds survive; explicit navigation clears neighborhood focus by the existing rule. Old-generation actions are rejected even when the next file has the same node IDs. List-only state changes stay inside AnalysisPanel, so they do not rerender the App/Canvas or request layout. This is verified statically, not a callback-leak audit or a formal performance measurement.

Severity is displayed without reinterpretation. Any graph-wide error keeps “Graph may be incomplete” visible regardless of list filters; the validated Canvas remains usable. Import rejection is distinct from recorded analyzer diagnostics, and a fatal CLI error is not inferred from a missing graph. Empty diagnostics and zero filter matches have different messages; zero diagnostics never guarantees complete analysis. Unknown relationships never create nodes or edges.

Confidence belongs to individual evidence: confirmed describes a stated static fact; best_effort describes limited heuristics/partial resolution. Unsupported/unknown relationships are not guessed. Diagnostic severity is not confidence, and mixed evidence is not collapsed into node confidence. injects remains requested_token (“Requests token” / “Requested by”), not implementation choice after an override, instance creation or runtime calls.

Recorded scope is parsed_named_class_methods / same_class_only. Examined/emitted/skipped are snapshot call-site counts, not whole-repository coverage, a quality percentage or deduplicated calls-edge counts. Skipped diagnostics are identified by validated skippedCount presence, not a code prefix; relatedNodeId/code retain method/reason attribution. One diagnostic with skippedCount=3 remains one row and three sites. File-only parse errors are not added to skipped totals. Neither filtering nor pagination changes the metadata counters.

Verification uses existing Vitest selectors/server-rendered React output and implementer browser checks with the actual File chooser, the hand-authored fixture and disposable validated inputs. Scope includes 123-row pagination, mixed severity, unknown codes, file/global notices, escaped Japanese/HTML-like text, zero diagnostics/calls, import rejection, generation replacement, keyboard controls and 800px layout. Captures and disposable files are outside the repository. No renderer mock, dependency, wire/schema/oracle or layout configuration changes. #14/#17 integration, real-repository analysis, #26 E2E, initial-user UX, formal accessibility/performance evaluation and exhaustive callback checks remain unimplemented or unverified.

## Copy Context (#24)

Copy Context takes the validated snapshot and selected canonical ID, never a projection or UI filter. Fixed section order: Component; Snapshot; outgoing relationships; incoming relationships; direct methods; declared endpoints on controllers requesting this token; endpoint handler static calls; endpoint controller requested tokens; node declaration evidence; edge relationship evidence; relevant diagnostics; same-source-file notices; Analysis scope / unknown; Truncation. Empty optional data sections are omitted. Each relationship, method, two-edge path, evidence record or diagnostic is one item in its fixed section (maximum 50); no per-node subsections evade the limit. Component and mandatory notices are fixed singleton blocks.

Only incident edges and parentId+contains direct methods are collected. Three dedicated paths start at the selection: Token <- injects <- Controller -> exposes -> Endpoint; Endpoint -> depends_on -> Method -> calls -> Method; Endpoint <- exposes <- Controller -> injects -> Token. Discovered nodes are not expanded. A path keeps both original directed edges, its intermediate node and separate evidence references; no synthetic edge is produced.

Candidates sort ordinally by kind/name/ID; endpoints use HTTP method/path/ID within their kind. Ties use original edge IDs and intermediate node identities; evidence uses the existing sortedEvidence tuple and diagnostics the existing sortedDiagnostics tuple. Sorting always precedes limiting and uses original unshortened values. Metadata key order, source array order, locale and UI state are not inputs.

Budget priority is section items, then 200 distinct related canonical IDs (excluding the selected component, including path intermediates), then Markdown characters. Rejected items do not consume node budget. Repeated references count once. Each omitted item has exactly one reason. Data fields are shortened to 160 Unicode code points separately and marked explicitly, before escaping. Context-local N/E references are not canonical IDs; original IDs are displayed as data, with a truncation marker when shortened, and are never shortened for identity comparison.

The complete Markdown is limited to 32,000 Unicode code points. A 6,500-code-point reserve holds scope, confidence, unknown counts and omission notices; optional data is admitted only as whole items after data escaping. Final output is counted again, with an error rather than a sliced document on overflow. Quoted graph data is single-line, with control characters encoded and Markdown/HTML punctuation escaped. The fixed tool template and notices are distinct from graph data; this is not a guarantee against LLM prompt injection or secrets in arbitrary input.

Graph-wide call counters retain their original scope/mode; they are not component coverage or edge counts. Relevant diagnostic summaries distinguish selected/actually included methods from candidate methods left out by limits, retaining row counts and skipped-site sums even when diagnostic rows are omitted. File notices have no node attribution and do not contribute to call counts. Snapshot-wide error presence and zero-is-not-complete warnings are mandatory. Node and edge evidence remain separate; confirmed and best_effort records are not collapsed into a node confidence. Snapshot time is original analyzedAt, never export time. No current-source synchronization or runtime behavior is guaranteed.


Copy Context is inside selected-node details. On an explicit click it captures the graph/ID and generated Markdown, writes plain text through navigator.clipboard.writeText, and shows the target name only after resolution. Generation failure copies nothing; write rejection, synchronous exception or unavailable API shows Copy failed and the same generated text in a readOnly, selectable textarea. There is no automatic retry, execCommand fallback, clipboard reading, network transmission or external app launch. The control owns local state and dispatches no Canvas actions. Details are keyed by the pair [import generation, selected ID]; unmount disposes the old result listener. One shared pending-write flag outlives details remounts, so a new target cannot start another OS write until the old one settles. This does not cancel an already started OS operation. A new target reports busy and allows explicit retry after settlement.

Verification for this local implementation: targeted Vitest checks separate pure candidate sets, escaped Markdown and Clipboard controller behavior; existing details/diagnostics/navigation tests remain in the target set. The 199/200/201 boundary exercises the exact tentative node-admission function with valid canonical candidate IDs; final Markdown additionally applies section and character limits, so not every candidate admission becomes a printed node. Whole rejected paths never reserve IDs. Fixtures above 50 items, long Unicode fields/evidence/diagnostics and actual character-budget omissions are asserted, not just an upper-bound check on small input.

Implementer browser checks used the actual File chooser and hand-authored fixture. UsersService, POST /auth/login and choose were copied using the real Clipboard path and pasted into a disposable localhost textarea. Complete output matched across kind filter, expansion/collapse, neighbor focus and diagnostic filter changes. Keyboard Enter, Reveal/navigation and the existing diagnostic list remained usable. Failure and delayed-write tests used a disposable Vite preview that replaced only the writer call: fallback text matched the generated write exactly; old success after selection change and old rejection after loading a same-ID/different-time snapshot did not update the new control. Those are simulated write outcomes, not naturally occurring browser permission denials. At 800px the 24,179-character UsersService fallback wrapped within its 718px textarea and all text was selectable. Observed warning/error logs were empty. No maintained E2E infrastructure was added.

Native Clipboard rejection, actual IME/pinch, first-use UX, screen-reader evaluation, exhaustive callbacks/layout invocation measurements, formal performance, real-repository analysis and automated E2E remain unverified. Copy/fallback noninterference with Canvas layout is a static state/dispatch conclusion, not a runtime layout count. The hand-authored fixture is not proof of complete Analyzer output; #14/#17 remain separate and production analyze remains nonzero/no-write. No Rust, schema, oracle, dependency/lockfile, CI or layout setting changes are part of this feature.
